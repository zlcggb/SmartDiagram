# 多轮对话意图识别提速与分步思考状态显示方案

本方案旨在解决用户在多轮对话时“等待思考时间太久”以及“无法获知当前思考进度”的痛点。

## 方案设计

### 1. 后端：多轮对话路由零延迟（极速免分类）

**问题**：用户在多轮交互中（如“这个能换一种风格，再刷一下”），后端仍可能再次调用大模型对意图进行分类，多出一次大模型调用耗时（3-10秒）。
**优化**：在 `router.py` 中放宽多轮对话的判断。只要当前画布上存在激活的引擎（`current_engine`）且当前属于多轮对话（`messages` 长度大于 1），且用户的请求没有强行命中其他引擎的关键字，就默认沿用当前引擎，完全跳过大模型分类，将路由耗时缩短至 0.0 秒。

### 2. 前端 + 后端：实时分步思考进度显示

**问题**：大模型生成首字前（包括路由、调度引擎和等待大模型响应），前端界面只有单调的“思考中...”，没有任何有价值的反馈。
**优化**：
- **后端**：在 `routes.py` 中，通过 `astream_events` 实时监听节点的启动与大模型调用的开始，向前端实时吐出 `type: 'status'` 格式的进度事件（例如：“🔍 正在分析您的修改意图...”、“🧠 正在通过智能模型路由分发任务...”、“✍️ 正在构思可视化方案与生成代码...”）。
- **前端**：
  - 在 `chatStore.ts` 的 `Message` 类型中新增 `statusText` 属性。
  - 在 `ChatPanel.tsx` 中，监听 `status` 事件并调用 `updateLastAssistantMessage` 将最新的阶段文字更新至 `statusText`。
  - 在未产生正式内容前，将“思考中”替换为 `msg.statusText || '思考中'` 动态展示当前的思考节点。
