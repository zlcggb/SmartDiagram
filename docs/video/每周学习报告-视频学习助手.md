## 事情一 · 销售培训体系知识学习

> **来源：** 本周安排的业务学习材料（公司营销数字化与培训体系背景介绍）  
> **说明：** 这部分是**业务知识学习**，与下面「项目部署」是两件独立的事。

### 1.1 我学到了什么

**（1）洲明业务基本情况**

- 洲明科技（Unilumin）是 LED 显示产品与解决方案提供商，国内 + 海外双线销售。
- 客户结构包括经销商、B 端项目客户、C 端用户，签约 / 非签约客户需要差异化运营。
- 产品线和方案讲解门槛较高（小间距、租赁、固装、创意显示等）。

**（2）营销数字化底盘已经比较完整**

公司以 **Salesforce CRM** 为核心，搭建了营销全域数字化体系，主流程包括：

| 流程 | 我理解的含义 |
|------|--------------|
| **MTL** | 从市场活动到产生销售线索 |
| **LTC** | 从线索跟进到签约回款 |
| **MCR** | 持续维护客户关系 |
| **ITR** | 从客户问题到解决闭环 |

周边还对接了 OA、SAP、数据中台、合同管理、企查查、400 呼叫中心、官网、社媒、HubSpot（海外）等系统。AI 也在智能获客、销售助手、方案生成、投标、合同审查等方向推进。

**（3）培训体系是目前明显的缺口**

- **已有的：** 营销流程在线、数据在线、AI 辅助业务在规划/落地。
- **还缺的：** 销售、渠道、工程师的**培训、认证、实战检验**缺少系统化载体；「人的培养」仍较多依赖零散文档和线下场次。
- **我的理解：** 营销数字化解决的是「流程和数据」，培训数字化要解决的是「人会不会、能不能用、能不能通过检验」——这是两块不同的事。

### 1.2 我的思考

（新人填写，示例供参考）

- 培训缺口最突出的可能是**产品知识传递**和**方案讲解能力**，因为产品线复杂、门槛高。
- 北森等正式培训系统可能是「正式载体」，但具体怎么和现有 CRM / 业务系统衔接，我还不太清楚。
- AI 可以辅助学习和测验，但**认证和档案**可能还需要正式系统来承担。

## 事情二 · 项目部署实践

> **说明：** 这部分是我本周**亲手完成的技术实践**——把一个 Docker 单容器 Web 应用部署到阿里云 ECS 并对外提供访问。  
> **与事情一的关系：** 部署的是一类「Web 应用」的上线过程；**不等于**公司销售培训体系本身，只是本周并行做的另一项工作。

### 2.1 我做了什么

| 步骤 | 内容 | 状态 |
|------|------|------|
| 1 | 购买 / 使用阿里云 ECS（Alibaba Cloud Linux 3） | ✅ |
| 2 | Workbench 远程连接，安装 Docker + Compose | ✅ |
| 3 | 配置国内镜像加速（DaoCloud） | ✅ |
| 4 | 上传项目代码，修改 Dockerfile 国内源 | ✅ |
| 5 | 配置 `.env.docker` 环境变量 | ✅ |
| 6 | `docker compose up --build -d` 构建并启动 | ✅ |
| 7 | 安全组放行 8000 端口，浏览器验收 | ✅ |

**部署结果：**

- 访问地址：[http://123.57.215.65:8000/](http://123.57.215.65:8000/)
- 应用类型：Docker Compose **单容器 Web 应用**（前后端同一容器，端口 8000）
- 健康检查：`/api/health` 返回正常即表示服务可用

### 2.2 部署过程中我踩过的坑

（新人填写，示例供参考）

| 问题 | 原因 | 怎么解决的 |
|------|------|------------|
| docker-compose-plugin 装不上 | 阿里云自带源没有该包 | 换 Docker CE 源，`sed` 把 releasever 改成 8 |
| 拉镜像 / pip 超时 | 国内直连 Docker Hub、PyPI 慢 | DaoCloud 镜像加速 + Dockerfile 改清华 pip 源 |
| GitHub clone 失败 | 国内 ECS 连 GitHub 超时 | 改成本机 zip 打包，Workbench 上传到 `/opt` |
| 浏览器打不开 | 容器正常但安全组没放行 | 入方向添加 TCP 8000 |
| 改 API Key 不生效 | 容器仍用旧环境变量 | `docker compose up -d --force-recreate` |

### 2.3 网站功能与使用说明（部署成果）

这个网站是一个**视频学习类 Web 应用**，主要能力：

| 功能 | 说明 |
|------|------|
| 本地上传视频 | 上传培训录屏进行分析（推荐） |
| AI 总结 | 生成大纲、要点、章节、思维导图 |
| AI 测验 | 生成题目，提交后看得分和解析 |
| 视频回看 | 可跳转到原视频对应时间点 |

**推荐使用流程：** 注册登录 → 本地上传视频 → 等 AI 总结 → 生成测验 → 提交看解析

### 2.4 使用注意事项（如需分享给他人试用）

| ⚠️ | 说明 |
|----|------|
| HTTP 未加密 | 当前是 `http://`，不要传敏感商业 / 客户数据 |
| AI 外发 | 视频内容会送外部 AI 处理，**不要上传涉密素材** |
| 内测性质 | 服务重启或一段时间后，部分记录可能丢失 |
| 与正式培训系统无关 | 这是本周部署的实践项目，**不是**公司正式 LMS / 北森培训系统 |
| 优先本地上传 | 培训录屏建议本地文件上传，外链解析可能受限 |

### 2.5 我的思考（部署向）

（新人填写，示例供参考）

- 这类「单容器 + compose」的项目，国内 ECS 部署关键是镜像加速和环境变量，流程可以复用到其他类似项目。
- 部署和「培训业务」是两条线：我学会的是**怎么让一个 Web 应用跑起来**，不是已经接入了公司培训体系。
- 如果以后培训系统也要上云，安全（HTTPS、权限、数据隔离）会是下一步要补的。
