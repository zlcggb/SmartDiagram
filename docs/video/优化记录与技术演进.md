# 优化记录与技术演进白皮书 · Performance & Algorithm Evolution

> **标准定义**：SmartDiagram 视频学习助手（VidGrab）与全平台多智能体核心性能攻坚、领域先验编译算法、全链路耗时透明化及 AI Agent 专项质量工程技术演进白皮书。  
> **生产基准 (v2.9.0 · 2026-10)**：基于 **React 18 单行工作台 (`apps/web/src/features/video`) + 首批字幕 3.5s 脉冲推流 + 6 线程 ASR (`6.7s`) 与主研报/双语翻译并行 (`35.4s`) + 端侧 MediaPipe 三合一视觉教练 (`/video/coach`) + 全平台 AI Agent 专项评测体系（83 样本 + 19 条确定性自愈规则 `Pass@Repair 100%`）+ Playwright SSE 混沌工程 + 50 路异步高并发压测 (`3,611+ streams/s`) + 本地/远程自动化部署自诊断闭环** 构筑的工业级研发与质量工程体系。

## 一、 技术演进背景与性能攻坚动机 (Evolution Background & Motivation)

在 VidGrab 早期版本中，系统虽然能够完成音视频解析与总结，但在用户体验和算法精度层面存在四处严重制约工业化落地的技术瓶颈：
1. **长达 45~60 秒的完全黑盒等待**：用户提交 30 分钟视频后，只能面对一个单调的加载圈盲等，极易引发误解导致强行刷新网页；
2. **垂直行业专业术语同音错别字严重**：通用 ASR 模型由于缺乏主题先验，在讲者带有地方口音或语速极快时，频繁将行业专业词汇转译为常见错别字（如将“八页纸”识别为“八夜死”，将“微服务治理”识别为“微服务志理”）；
3. **系统耗时黑盒无感知**：用户无法获知处理究竟卡在音频下载、语音识别还是大模型推理阶段；
4. **AI 总结流于泛泛流水账**：传统单轮 Prompt 生成的摘要缺乏行动指导意义，无法支撑战略决策与落地执行。

本白皮书系统记录了针对上述四大瓶颈展开的核心战役与最终工程架构沉淀。

## 四、 数据契约与耗时性能指标模型 (Data Contract & Timing Schema)

### 1. 全链路耗时打点数据模型 (`TimingStats`)

任务执行完毕后，状态机向客户端交付精确到毫秒的打点数据：

```typescript
export interface TimingStats {
  audio_ms: number;       // 音频下载、声学重采样与切片耗时 (毫秒)
  asr_ms: number;         // 语音识别总耗时 (毫秒)
  llm_ms: number;         // 大模型总结与研报生成耗时 (毫秒)
  total_ms: number;       // 全链路总耗时 (毫秒)
  speedup_ratio: number;  // 相比视频真实时长的加速比倍率 (如 12.5x)
}
```

### 2. 领域先验编译器 Prompt 组装规范 (`cloud_asr.py`)

```python
def build_asr_system_prompt(title: str = "", topic_context: str = "") -> str:
    """构建领域先验编译器系统提示词，严防专业词汇同音字与口音拼写偏误。"""
    prompt = (
        "你是一个极其专业的中文流式语音识别转写引擎。\n"
        "【核心排版与用词规范】：\n"
        "1. 一律输出规范的标准简体中文，严禁夹杂任何日文假名、韩文字符或异形符号；\n"
        "2. 深度结合上下文逻辑，智能识别并校正讲者由于口音（如平翘舌不分、z/zh、l/n 混淆）造成的同音错别字；\n"
        "3. 遇到代码、开源项目名、行业专业术语，必须按标准行业拼写输出（如 Kubernetes, Redis, Docker, FastAPI）。\n"
    )
    if title or topic_context:
        prompt += f"\n【当前视频背景先验】：\n视频标题：{title}\n核心领域关键词：{topic_context}\n请在转写中优先对齐上述垂直领域术语。"
    return prompt
```

### 1. 领域先验识别失败时的平滑兜底
若视频标题过短（如仅为“1.mp4”或纯表情符号），领域先验编译器自动退化为基础标准提示词，强制约束“标准简体中文 + 禁止日文字符假名”，杜绝大模型在缺乏先验时强行猜测。

### 2. 云端 ASR 并发超时与本地 Whisper 降级
在调用云端 6 线程并发转写（`ASR_MAX_WORKERS=6`，早期为 3 线程）时，若单片请求超过 15 秒未响应或云厂商返回 5xx 错误，系统自动捕获异常并熔断降级至本地 `faster-whisper`（采用 base/small 模型），同时前端进度条精细打点由 63% 平滑推进至 92%，保证任务 100% 成功交付。

## 七、 [2026-10-23] v2.6.0 双系统 SSE 流式问答、秒级 Range 跳转与云端共享 Jeff 生产落地

### 1. 背景痛点与基线数据
在将系统 1 决策模型 **Jeff (`gliformer-large-v1`)** 与 VidGrab 全栈部署至云服务器（`vidgrab.unilumin-gtm.com`）生产环境后，面临四项关键工程瓶颈：
1. **云服务器容器内存 OOM (Exit 137)**：`gliformer-large-v1` 在 PyTorch 默认加载模式下经历「CPU 字典反序列化 + 模型结构构建 + 权重复制」三重峰值，瞬时内存飙升至 **4.81 GB**，触发宿主机 OOM Killer；
2. **问答交互非流式且耗时黑盒**：`POST /api/ask` 采用同步阻塞等待，大模型生成长回答需盲等 5~15 秒，且气泡底部仅展示单一延迟，无法区分 **系统 1 (Jev) 意图路由用时** 与 **系统 2 (大模型) 推理用时**，刷新页面后问答历史即丢失；
3. **点击回答中的时间戳胶囊（如 `▶ 00:26`）视频总是从 `00:00` 重新开始**：无法定位到目标秒数；
4. **历史记录回放与管理后台报错**：刚完成的任务在「学习记录」点击「查看研报与回放」停留在首页；管理后台 `GET /api/admin/stats` 报 `500 Internal Server Error`。

### 2. 底层根因剖析 (First Principles)
- **Jeff 内存膨胀根因**：`pytorch_model.bin` (Pickle) 反序列化必须在匿名物理内存中完整展開副本；同时 `gliformer` 自定义层（`Fourier1DPositionEmbedding.frequencies` 与 `anchor_normalization._validated_eps`）未兼容 PyTorch `meta` 设备延迟初始化。
- **时间戳点击归零双重根因**：
  1. **Nginx 全局缓存剥离 `Range` 头**：宝塔 Nginx `/www/server/nginx/conf/proxy.conf` 默认开启 `proxy_cache cache_one;`。在缓存未命中时，Nginx 会剥离客户端的 `Range: bytes=...` 请求头向后端拉取全量文件并返回 `HTTP 200 OK`（从第 0 字节下发），导致浏览器 `<video>` 强制重置播放进度为 `00:00`；
  2. **播放器未初始化态覆盖**：当视频处于未点击播放的初始态（`readyState === 0`）时，直接设置 `xgPlayer.currentTime = t` 再调用 `play()` 会被首次流加载重置为 `0`。
- **历史回放与后台 500 根因**：
  - `GET /api/summary/{task_id}` 命中内存 `_tasks` 分支时漏返 `video_id`、`webpage_url`、`source_type` 等 5 个字段，导致前端 `hasWorkspace` 计算属性为 `false`；
  - PostgreSQL `SUM(storage_bytes)` 返回 `decimal.Decimal`，与 `float` 相除触发 `TypeError`。

## 八、 [2026-10-24] v2.7.0 统一平台融合：SmartDiagram 跨工作台协同、四点并发极速总结 (35.4s)、高置信意图门控与 Apple 闯关测验双持久化

### 1. 迭代背景与核心痛点

在将 VidGrab 视频学习助手全面融合进 **SmartDiagram** 统一平台（`/video`）的过程中，我们针对工程架构、AI 总结速度、问答意图准确度与学习测验交互进行了深度重构：
1. **单平台孤岛与导图割裂**：原 Vue 3 独立应用无法与 SmartDiagram 的多引擎画布工作台（MindElixir / Mermaid / Excalidraw）联动；
2. **AI 总结与翻译串行耗时偏长**：原流程在音频切片转写后串行生成主总结与双语翻译，端到端耗时约 `58.8s`；
3. **预设引导提问被小模型误路由**：用户点击「请用三句话概括这个视频讲了什么」或开放式提问时，偶发被系统 1 (`Jeff`) 以低置信度误判为 `make_quiz` 或 `download` 功能动作；
4. **学习测验交互与持久化缺失**：传统长表单测验刷题体验疲劳、全卷模式无法顺畅滚动，且刷新页面后生成的测验题目与成绩丢失。

### 2. 核心技术突破与架构升级

- **🏛️ SmartDiagram Monorepo 全栈融合 (`apps/web/src/features/video` + `apps/api-video :4020`)**：
  - 前端全面迁移至 **React 18 + TypeScript + Tailwind v4**，定制专属单行紧凑毛玻璃导航栏（`VideoShell.tsx`），并将解析后的紧凑视频切换条通过 React Portal 嵌入顶栏中央槽位，支持一键将视频思维导图发送至 `/diagram` 画布深度编辑。
  - 视频卡片自动识别 **🎵 抖音 / 📺 Bilibili / 📕 小红书 / ▶️ YouTube** 等平台彩色徽章，下载进度达 100% 自动触发浏览器流式保存，消除二次确认弹窗。
- **⚡ 四点并发极速总结管线 (`58.8s ➔ 35.4s`，提速 40%+)**：
  1. **FFmpeg 极速直拷与并发切块**：`asr_cloud.py` 支持直接对 `.mp4` 容器执行 `-vn -ac 1 -ar 16000` 极速重采样与 `6` 线程并发切片；
  2. **ASR 动态并发提速**：音频分块并发度提升至 `ASR_MAX_WORKERS=6`，210 秒音频转写耗时压降至 `6.7s`；
  3. **研报生成与字幕翻译双线程并行 (`ThreadPoolExecutor`)**：在 `summarizer.py` 中将 ` _call_llm` 主研报生成与 `_translate_segments_parallel` 双语对照翻译并行投递，消除串行等待；
  4. **工业级 CJK + 可视化流程卡片 Markdown 引擎 (`markdown.ts`)**：自研支持中文全角标点紧邻 `**加粗**`、单星号 `*话术示范*` 胶囊徽章、以及自动将 `[阶段一] -> [阶段二]` 围栏块升维渲染为横向递进流程卡片。
- **🧭 系统 1 (Jeff) 三层高置信意图门控 (`intent_router.py`)**：
  - 引入 **知识总结/概括硬优先白名单 (`_SUMMARY_QA_PRIORITY_RE`)** + **功能性意图特征词二次核验** + **`0.78` 高置信度阈值门控**，开放式提问与预设引导词 100% 稳定路由至 `video_qa` 总结问答。
- **🎯 Apple Study Deck 动态闯关卡片 + 紧凑电子全卷 + 双重持久化 (`quiz_generator.py` / `QuizPanel.tsx` / `repo.py`)**：
  - 出题引擎升级为 **时间桶均匀采样 + 研报骨架双源融合 + Bloom 四维认知分层 + 6 题极速生成（8~11s）**；
  - 前端支持 **🎴 闯关卡片**（即选即判、解析折叠、底部固定操作栏）与 **📋 全卷模式**（紧凑电子考卷流式滚动、全部/错题筛选）无缝切换；
  - 后端新增 `save_analysis_quiz_data`、`get_latest_quiz_bundle_for_analysis` 与 `POST /api/quiz/state`，配合前端 `localStorage` 实现题目、作答进度与成绩在 PostgreSQL `analyses.result.quiz_data` 及 `quizzes` 表的双重持久化。

## 十三、 v2.8.2 移动端视觉教练精修：摄像头等比无畸变取景、动态降帧错峰防卡顿与画面内全局暂停 HUD

### 1. 需求背景与移动端实测痛点
在手机端竖屏使用 AI 视觉分析教练（`/video/coach`）时发现三项核心体验瓶颈：
1. **前置摄像头画面拉伸变形**：手机竖屏下传感器返回的 `videoWidth × videoHeight` 为竖屏比例（如 `480×640` 或 `720×1280`），此前直接 `ctx.drawImage(video, 0, 0, 640, 360)` 强行绘制到 16:9 横屏画布，导致人物面部被横向拉宽逾 2 倍。
2. **中低性能机型识别微卡顿**：原本固定每 `55ms`（18 FPS）在同一主线程帧内连续同步跑完 `Pose (Full)` + `Hand (42点)` + `Face (478点)` 三个 WASM 模型，且非分析态仍高频创建临时 DOM `<canvas>`，造成移动端周期性掉帧。
3. **移动端页面布局拥挤与警告框遮挡**：手机端顶栏文字与倒计时徽章重叠、视频左上角与右上角 HUD 胶囊碰撞、下方按钮过大，且自动暂停时的黄色提示框占去近 1/3 屏幕高度并将文字挤成 4 字宽窄列。

### 2. 核心技术修改与架构收益
1. **等比自适应取景与前置自然镜像引擎（`drawVideoFrameAdaptive` @ `edgePerceptionEngine.ts`）**：
   - 实时计算源视频 `videoWidth / videoHeight` 与目标 Canvas 的真实宽高比，支持 **`cover`（等比居中裁剪，默认用于摄像头）** 与 **`contain`（等比完整保留，默认用于本地视频）** 一键切换，**100% 保持 1:1 原始像素比例，彻底消除拉伸变形**。
   - 前置摄像头（`cameraFacing === 'user'`）自动开启水平自拍镜像，并在镜像后的无畸变画布上执行 MediaPipe 检测与正向文字标注（文字不反显、左右手智能对齐）；`composeRealTemporalGridBundle` 合成 2×2 四格图时同步跟随采样帧真实宽高比。
2. **设备性能自适应帧率与多模型奇偶帧错峰调度（`RealMediaPipeHolisticService` @ `edgePerceptionEngine.ts`）**：
   - 实时监测单次推理耗时 `avgInferCostMs`，支持 **`auto`（智能自适应 18/12/8 FPS）**、**`eco`（省电流畅 8.5 FPS）**、**`high`（高帧率 20 FPS）** 三档动态调节。
   - 在移动设备或单帧耗时偏高时自动启用**奇偶拍错峰推理（Staggered Inference）**：偶数拍运行 `PoseLandmarker`，奇数拍运行 `HandLandmarker` + `FaceLandmarker`，未运行层复用 EMA 平滑缓存，**单帧主线程峰值阻塞耗时直降 50%**；暂停预览态实现零临时 Canvas 分配。
3. **画面内毛玻璃全局暂停覆盖层（In-Video Global Pause Overlay）与紧凑布局重构（`VideoCoachLabPage.tsx`）**：
   - 移除外部占空间的黄色警告横幅，改为直接叠加在视频取景框内的**半透明毛玻璃全局暂停层**，居中展示状态说明与 `▶ 继续实时分析` / `🔑 登录解锁单次2分钟` / `👁 仅看画面` 胶囊按钮，实现零 CLS 布局跳动。
   - 精简手机端顶栏信息密度，重排视频框四角 HUD（左下角整合 `[🔄 前置/后置]`、`[📐 满屏/完整]`、`[🤖 智能帧率]`），并将下方控制按钮与模式栏瘦身为紧凑 36px 工具条与 iOS 分段控制器。

## 十四、 v2.9.0 重大演进：全平台 AI Agent 专项评测体系（83 样本）、SSE 混沌/高并发压测、自动化部署自诊断闭环与 15 道核心架构/质量面试题库沉淀

### 14.1 升级背景与核心破局

随着 SmartDiagram 演进为涵盖 **AI 图表工作台（9 大渲染引擎）、AI 演示文稿（LangGraph 并行编排）、AI 招聘初筛（`Rubric-v3`）、视频学习助手（System 1/2 协同与双源测验）及 AI 视觉教练** 的多智能体协同平台，工程与质量体系面临四大深水区挑战：

1. **大模型非确定性输出难断言（Non-Determinism vs. Deterministic QA）**：
   - **痛点**：LLM 生成的 Mermaid、Draw.io XML、Excalidraw JSON、ECharts 配置或 HTML 邮件常带有 Markdown 围栏残留、未转义括号、缺失根节点或闭合标签等非致命语法瑕疵；传统基于字符串匹配的测试极易产生 Flaky 误报，而盲目放宽断言又会漏放真实渲染崩溃与 XSS 注入。
   - **破局**：构建 **「四层契约校验（`validate_diagram_output`）+ 19 条零 Token 开销确定性自愈算子（`repair_diagram_output`）」**，在评测体系中严格分离 **`Pass@1`（模型原生输出合格率）** 与 **`Pass@Repair`（自愈后最终交付合格率）**，实现 17 条可修复语法残缺 Badcase 从 **`Pass@1 = 0.0%` 到 `Pass@Repair = 100.0%`** 的零延迟自愈，同时对 3 条含 `<script>` / 函数注入 / `javascript:` 的恶意样本执行 **100% 红线阻断（绝不带病修复）**。
2. **跨模块办公 Agent（图表/PPT/招聘/视频）缺统一回归门禁**：
   - **痛点**：多个垂域 Agent 共享底层基础设施，缺乏秒级离线回归基准极易导致“改了图表路由影响视频门控”或“提示词微调导致招聘评分幻觉回潮”。
   - **破局**：沉淀 **83 样本全平台黄金评测集与 Badcase 回归矩阵**（图表与办公制品 **53 样本** + 招聘/视频/PPT 跨模块多模态 **30 样本**），重点覆盖 AI 招聘 `Rubric-v3` **原文证据子串核验防幻觉降级**与 **Knockout 一票否决硬顶（`<= 59` 分）**、视频助手 **Jeff 三层高置信意图门控纠偏**与**四题型确定性判分**、以及 PPT **LangGraph `Send` 并行扇出保序与单页异常隔离**。
3. **流式 SSE 弱网断流、截断帧与高并发护栏难自动化**：
   - **痛点**：生产环境中客户端 `EventSource` / `ReadableStream` 面对网络闪断、跨 chunk 截断 JSON 帧、HTTP 429 突发限流与 502 网关抖动时的 UI 状态机恢复极难通过传统单元测试覆盖；同时多租户高并发流式输出下的限流水位线精度、死循环熔断与 Redis 宕机降级缺乏量化基准。
   - **破局**：自研零外部 LLM 开销的 **`SpaTestServer` + Playwright Headless Chromium 6 场景混沌故障注入套件**，以及基于 `asyncio` 的 **50 路高并发 SSE 流压测与运行时护栏基准套件（峰值吞吐 `3,611.17 streams/s`、`92,951.59 chunks/s`）**。
4. **服务器手工拉代码部署失败黑盒无反馈**：
   - **痛点**：此前习惯“本地修改直接 `git push`，再 SSH 登录服务器执行 `./deploy.sh --update`”，一旦因 `.env` 漏配、破坏性迁移或容器健康检查超时导致部署中断，缺乏结构化现场快照与主动告警。
   - **破局**：打通 **「本地 `pre-push` 8s 快速安检门（`scripts/local-preflight.sh`）➔ 本地一键远程发布与失败快照拉取（`scripts/remote-deploy.sh`）➔ 服务端 `deploy.sh` 阶段级 `DEPLOY_STAGE` 捕获与 `scripts/deploy-notify.sh` 敏感信息正则脱敏 Webhook 告警」** 全链路闭环。

## 十五、 v2.9.1 学习社区与知识共享全栈升级：三处一键发布、双栏互动详情、首帧封面双通道截取与 Apple 级内置弹窗

### 15.1 升级背景与核心痛点
1. **单机学习孤岛**：用户在完成视频 AI 研报、章节拆解、思维导图与闯关测验后，缺乏将优质视频学习成果沉淀为团队公共知识资产的通道。
2. **卡片纯文字缺乏视觉锚点**：「学习记录」与「学习社区」列表卡片原先仅有标题与摘要文字，缺少视频画面缩略图，浏览辨识度低；且历史存量视频尚未生成封面。
3. **跨页状态不同步与原生弹窗割裂**：工作台点击「发布到社区」或「下架」后未实时同步当前页按钮状态（需手动刷新页面），且沿用浏览器原生 `window.confirm` / `alert`，与 Apple Glass 视觉风格割裂。

### 15.2 核心技术实现与架构演进
1. **学习社区与分享全栈闭环（Migrations `004~007` + `share_routes.py` + `community_routes.py`）**：
   - 演进 `shares`、`share_likes`、`share_favorites`、`share_comments`、`share_reports` 与 `videos.cover_url` 表结构；
   - 支持**工作台顶栏**、**学习记录卡片**与**社区详情页**三处一键发布/重新上架/下架，采用 `INSERT ... ON CONFLICT (analysis_id) DO UPDATE` 幂等切换 `visibility`（`community` / `unlisted` / `revoked`）；
   - 操作完成后即时就地更新 React 状态机（`shareState`）并派发 `vidgrab:community-updated` 全局事件，彻底告别手动刷新页面。
2. **社区作品详情页左移互动区与内置弹窗系统（`VideoCommunityPostPage.tsx` + `VideoDialog.tsx`）**：
   - 将点赞、收藏与心得评论面板移至**左侧视频播放器正下方**，右侧 100% 留给 AI 深度研报、章节导览、Mind Elixir 思维导图、双语字幕与自测题库，消除视线遮挡；
   - 新增 `useVideoDialog()` Promise 化内置毛玻璃弹窗与顶部悬浮 Toast，全面替换原生 `confirm` / `alert`。
3. **视频首帧封面双通道自动截取与「左文右图」卡片重构（`VideoPlayer.tsx` + `media_routes.py` + `VideoCoverThumb.tsx`）**：
   - **前端 HTML5 `<video>` 首帧截取**：监听 `loadeddata`，若位于片头黑场自动微调至 `0.8s` 抽帧，通过 Canvas 等比缩放输出 `480px` JPEG DataURL 并同步调用 `POST /api/media/cover` 持久化（修复 React 18 状态批处理导致 `existingCoverUrl` 提前置位而跳过保存的竞态问题）；
   - **后端 `ffmpeg` 异步兜底与存量回填**：在 `POST /api/media/prepare` 解析出可播放流或本地缓存时，若 `cover_url` 为空自动派发后台守护线程调用 `ffmpeg -ss 0.8 -frames:v 1 -vf scale=480:-2` 抽帧落库，并对云端存量记录完成全量回填；
   - **卡片左文右图布局**：抽象 `VideoCoverThumb` 组件，在学习社区与学习记录卡片右侧渲染 `136×88` 圆角封面缩略图（高斯模糊氛围底衬 + 悬停微缩放 + 播放角标）。
