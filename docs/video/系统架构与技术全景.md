# 系统架构与技术全景 · SmartDiagram 视频学习助手 (`/video`) v2.7.0 工业级架构白皮书

> **文档性质**：本文档为 SmartDiagram 视频学习助手（`/video` 工作台，原 VidGrab 核心引擎）全栈系统的核心技术架构基准规范（Architecture Baseline Specification v2.7.0 · 2026-10）。  
> **设计哲学**：坚守“Monorepo 统一融合、四点并发极速流水线、快慢双系统协同、渐进交付（Progressive Delivery）与防线闭环”的第一性工程原则，所有拓扑与数据流转 100% 严密对齐生产代码。

---

## 一、 系统全栈架构全景拓扑

SmartDiagram 视频学习助手（`/video`）已从早期独立仓库全面融合进 **SmartDiagram Monorepo 统一工作台**，将跨平台多媒体获取、高并发声学计算、快慢双系统认知推理与关系型持久化深度拆解为六大高度内聚、松散耦合的子系统：

1. **统一前端交互层 (`apps/web/src/features/video/`)**：基于 **React 18 + TypeScript + Vite + Tailwind v4**。配备专属 Apple 毛玻璃单行导航栏（`VideoShell.tsx` + React Portal 顶栏居中切换条 `#vidgrab-navbar-center-slot`）、自适应横竖屏原生 HTTP 206 Range 播放器（`VideoPlayer.tsx`）与彩色来源徽章一键流式下载卡片（`VideoDownloadCard.tsx`），以及右侧六维 AI 学习面板（`SummaryPanel.tsx`：自研 `markdown.ts` 深度研报、**MindElixir** 交互导图与一键移交 `/diagram` 画布、双语对照字幕、快慢双系统 SSE 流式问答、Apple Study Deck 闯关卡片 / Paper Sheet 全卷双模式 AI 测验 `QuizPanel.tsx`）。
2. **网关、微服务与快慢双系统路由 (`gateway :9237` + `apps/api-video :4020` + `Jeff :8001`)**：本地开发由 Vite `:5173` 通过 `/video-api/*` 代理至 `apps/api-video` (`:4020`)，生产环境由 `gateway :9237` (Nginx) 统一分流。内建内存任务状态机（1.2s 渐进轮询）、全链路分段耗时打点器、异步取消熔断器（`SummaryCancelledError`），以及 **系统 1 (`Jeff :8001`, `gliformer-large-v1`)** Safetensors `mmap` 零拷贝常驻（`685 MiB`）三层高置信意图门控（`intent_router.py`）。
3. **音视频预处理流水线 (Media Ingestion Pipeline)**：多平台爬虫集群（🎵 抖音 4 线程分片 / 📺 B站 WBI / ▶️ YouTube / X / 📕 小红书 xhshow / 🎵 TikTok）、本地音视频缓存注册池、FFmpeg 单步极速声学重采样（16kHz Mono 16-bit PCM WAV）及 TikTok HEVC 优先 H.264 自动转码交付。
4. **6 线程高并发流式语音转写引擎 (`asr_cloud.py`)**：YouTube 原生字幕 0.3s 直通提取 ➔ **6 线程切片并发 ASR (`ASR_MAX_WORKERS=6`)** + 动态领域先验编译器（`build_asr_system_prompt` 零同音错别字）+ `on_chunk_done` 3.5s 首片字幕流式回传（210s 视频转写仅需 `6.7s`）➔ 本地 `faster-whisper` 兜底（base/small 模型，打点 63%~92% 进度）。
5. **双线程并行智库研报与双源融合出题引擎 (`summarizer.py` + `quiz_generator.py`)**：**主研报生成与双语字幕翻译双线程并行 (`ThreadPoolExecutor`)**，消除串行等待，将 210s 视频端到端总耗时从 `58.8s` 压降至 **`35.4s`**（提速 40%+）；研报涵盖四大篇章，配合时间桶均匀采样 + 研报骨架双源融合 + Bloom 四维认知分层极速出题引擎（默认精选 6 题：单选 3 + 多选 1 + 判断 2，耗时从 `~25s` 降至 `~9s`）。
6. **关系型存储与双重持久化商业体系 (`PostgreSQL 16` `vidgrab` 库 + `localStorage` + Stripe)**：全面升级为 **PostgreSQL 16 (`vidgrab` 数据库)**，涵盖 `users`、`videos`、`analyses`（`result` JSONB 内含研报、`chat_history` 多轮问答、`quiz_data` 测验与作答状态）、`quizzes`、`quiz_attempts` 表，配合前端 `localStorage` 双写实现游客与登录用户的全链路双重持久化；「学习记录 (`VideoHistoryPage.tsx`)」实时展示 `🎯 测验 XX分` 与回放直达，并集成 Stripe 托管收银台与 Webhook 幂等验签。

## 二、 四点并发极速总结管线与异步熔断时序规范

为彻底根除传统视频工具“用户面对进度条盲等数十秒”的焦虑痛点，SmartDiagram `/video` v2.7.0 打造了**四点并发极速总结管线（3.5s 首片字幕流式回传 + 6 线程并发 ASR + 研报与双语翻译双线程并行）**及**全链路耗时透明度打点**机制。

### 1. 核心时序时延基准
- **YouTube 0.3s 直通**：优先通过 `youtube-transcript-api` 或官方 VTT 抽取，免除音频重采样与 ASR 网络开销。
- **FFmpeg 单步重采样与 6 线程并发 ASR (`ASR_MAX_WORKERS=6`)**：长音频经 FFmpeg 单步重采样为 16kHz 单声道 WAV 并并发切片，第一片仅耗时 1.2s 完成抽音；云端 ASR 仅需 2.3s 完成首片识别，**合计 3.5s** 触发 `on_chunk_done` 回调，首批字幕直接呈现在前端。对于 210s 标准视频，全量切片转写耗时仅需 **`6.7s`**。
- **主研报生成与双语字幕翻译双线程并行 (`ThreadPoolExecutor`)**：彻底消除早期主研报与双语字幕串行等待瓶颈，在 `summarizer.py` 中通过双线程并行投递 LLM 任务，使 210s 视频端到端总耗时从 `58.8s` 压降至 **`35.4s`**（整体提速 40%+）。
- **全链路透明计时与取消强熔断机制**：前端实时挂载动态秒表（Live Stopwatch ⏱️，200ms 刷新周期），任务完成后常驻展示精确耗时徽标。当用户点击取消或离开页面时，调用 `/api/summary/cancel/{task_id}`，后台线程与协程在 `ensure_not_cancelled()` 检查点抛出 `SummaryCancelledError`，在 200ms 内强行阻断下游计算并释放临时文件。

#### 后端协议模型与校验器 (`apps/api-video` Python Pydantic v2)

```python
from typing import List, Optional, Dict, Any
from pydantic import BaseModel, Field, field_validator

class ChapterItem(BaseModel):
    time: str = Field(description="时间戳 mm:ss 或 hh:mm:ss")
    title: str = Field(description="章节主题标题")
    summary: str = Field(description="本章节核心要点阐释")

class SummaryReportModel(BaseModel):
    title: str = Field(..., min_length=2, description="精炼主题标题")
    tldr: str = Field(..., min_length=30, description="核心破局结论，150-250字")
    summary: str = Field(..., min_length=100, description="四篇章研报长文")
    key_points: List[str] = Field(default_factory=list, min_length=1)
    actionable_takeaways: List[str] = Field(default_factory=list, min_length=1)
    chapters: List[ChapterItem] = Field(default_factory=list)
    mindmap: str = Field(..., description="Markdown 知识体系树语法")
    chat_history: Optional[List[Dict[str, Any]]] = Field(default_factory=list)
    quiz_data: Optional[Dict[str, Any]] = Field(default=None)

    @field_validator("key_points")
    @classmethod
    def ensure_dimension_tag(cls, v: List[str]) -> List[str]:
        """规范化论点列表，若大模型未输出维度标签，自动补齐【核心洞察】"""
        normalized = []
        for item in v:
            text = str(item).strip()
            if not text.startswith(("【", "[")):
                text = f"【核心洞察】{text}"
            normalized.append(text)
        return normalized
```

### 4. 自愈式 JSON 修补流水线架构 (JSON Healing Pipeline)

大模型在流式输出超长 JSON 时，极易产生包裹 Markdown 围栏、控制字符未转义、或因 Token 截断导致的坏括号。系统构建了**四阶无损自愈解析链路**：

1. **围栏剥离 (Fence Stripping)**：
   正则 `r"```(?:json)?\s*([\s\S]*?)\s*```"` 提取正文，丢弃外围解释性叙述。
2. **字符转义修复 (Control Character Healing)**：
   扫描并纠正长文本中未正确转义的非合法双引号、控制字符与物理换行。
3. **括号与逗号自愈 (Bracket & Trailing Comma Auto-Fix)**：
   自动修补尾部多余的逗号 `,`；根据栈深度在末尾智能补全缺失的 `}` 和 `]`。
4. **Pydantic 宽容模型校验 (Schema Validation)**：
   装载至 `SummaryReportModel`，以缺省值填充非核心字段，写入 PostgreSQL 16 `analyses` 表 JSONB 字段，确保 100% 零崩溃交付。

## 四、 极端异常防御与高可用降级矩阵

系统针对网络波动、平台反爬、第三方 API 故障及超长视频，构建了多层级防御闭环：

| 故障场景 | 探测机制 | 降级容灾路径 | 用户感知与状态码 |
|---|---|---|---|
| **YouTube 原生字幕失效** | `fetch_youtube_subtitles()` 返回空 | 降级至 FFmpeg 单步抽音 ➔ 云端 6 线程 (`ASR_MAX_WORKERS=6`) 切片识别 | 界面展示“未找到平台字幕，正在云端识别语音…” |
| **云端 ASR 欠费/限频/网络失败** | HTTP 401 / 403 / 429 或返回空文本 | 自动无缝降级至本地 `faster-whisper`（base/small 模型） | 进度条打点 63%~92%，提示“正在本机识别语音” |
| **视频无旁白或背景音乐喧宾夺主** | 语音转写结果有效文本字符 &lt; 50 | 触发 `_enrich_with_vision()`，按关键场景抽帧进行视觉理解 | 研报包含场景与画面描述多模态分析 |
