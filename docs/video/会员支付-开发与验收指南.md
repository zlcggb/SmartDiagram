# 会员支付开发与沙箱验收指南白皮书 · Billing Sandbox & E2E Testing

> **标准定义**：SmartDiagram 视频学习助手（`/video` v2.7.0）商业化体系本地联调、Stripe CLI 沙箱隧道搭建与自动化端到端验收工程指南。  
> **生产基准**：基于 **Stripe 官方 CLI 工具链 (`stripe listen` / `stripe trigger`) + SmartDiagram 平台统一认证与配额中心 + PostgreSQL 16 (`vidgrab` 库) 事务断言** 的完整测试闭环（注：早期单文件 SQLite 沙箱已演进为 PostgreSQL 16 连接池与平台级配额体系）。

## 一、 业务背景与沙箱联调痛点 (Background & Sandbox Rationale)

在商业支付系统研发阶段，直接在公网部署并使用真实信用卡进行联调存在极高的合规风险与测试成本。同时，内网本地开发环境（`localhost:8000`）缺少公网固定 IP 与 HTTPS 证书，传统依赖第三方向导反向代理（如 ngrok、frp）面临三大瓶颈：
1. **连接不稳定且延迟不可控**：第三方隧道免费版连接频繁断开，导致 Webhook 异步推迟或丢失；
2. **敏感密钥安全外泄隐患**：未经审计的公网端口映射可能导致本地开发数据库遭受恶意扫描；
3. **无法精准模拟复杂事件**：难以手动触发如“扣款失败智能重试”、“周期自动顺延续费”等长周期边缘事件。

VidGrab 官方确立了**“基于 Stripe 官方 CLI 专有安全隧道 + 本地动态签名热注入 + 确定性脚本自动化推演”**的沙箱工程基准。

## 四、 环境配置与密钥契约 (Environment Configuration & Secret Contract)

在 `backend/.env` 或 `local.env` 中，必须配置以下环境变量：

```ini
# Stripe 开发者沙箱密钥 (以 sk_test_ 开头)
STRIPE_SECRET_KEY=sk_test_51Pxxxxxxxxxxxxxxxxxxxxxxxxx

# 由 stripe listen 命令生成的本地签名密钥 (以 whsec_ 开头)
STRIPE_WEBHOOK_SECRET=whsec_xxxxxxxxxxxxxxxxxxxxxxxxxx

# 本地 JWT 签名密钥 (随机 32 字符以上字符串)
AUTH_JWT_SECRET=super_secret_jwt_random_key_vidgrab_2026

# 本地 SQLite 数据库存储绝对路径
APP_DB_PATH=/Users/zora/WorkData/项目app/app/free-video-downloader/backend/data/app.db
```

官方沙箱测试卡号矩阵：
- **卡号**：`4242 4242 4242 4242`
- **有效期**：未来任意月份与年份（如 `12/34`）
- **CVC**：任意 3 位数字（如 `123`）
- **邮编**：任意 5 位数字（如 `90210`）
