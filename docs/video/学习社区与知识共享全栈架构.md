## 二、核心功能设计详解

### 1. 一键发布与多入口状态同步 (`🚀 发布到社区`)

为了降低团队成员分享优质视频研报的操作阻力，系统在两个高频触点提供**免二次确认弹窗的一键直发体验**：

| 触点位置 | 未发布状态 | 已发布状态（当前页即时刷新） | 核心交互 |
|---|---|---|---|
| **视频工作台 (`SummaryPanel.tsx`)** | `🚀 发布到社区` 蓝色胶囊按钮 | `🌐 已发布社区` + `查看` + `下架`（若有新版则显示 `同步新版`） | 总结完成后点击即发，无需刷新浏览器页面，按钮状态毫秒级切换 |
| **我的学习记录 (`VideoHistoryPage.tsx`)** | 卡片底部 `🚀 发布到社区` 按钮 | 卡片顶部 `🌐 已分享至社区` 徽章 + 底部 `🌐 社区页` 与 `下架` | 支持在历史记录列表直接批量分享或一键下架 |
| **学习社区 · 我的发布 (`VideoCommunityPage.tsx`)** | 若已下架显示 `重新一键发布` | 显示 `公开展示` / `有新版可同步` + `下架` | 支持随时撤回公开状态或一键恢复上架 |

### 2. 视频首帧自动截取与历史无图记录自动补全

针对视频链接（抖音、B 站、小红书、YouTube 等）外链封面易防盗链失效（`403 Forbidden`）或临时签名过期的问题，我们设计了**前端 `<canvas>` 智能截帧 + 后端 `ffmpeg` 异步兜底**的双保险永久封面方案：

1. **前端 `<VideoPlayer>` 读取完成即自动截帧**：
   - `<video>` 元素开启 `preload="auto"`，在视频流准备完成触发 `onLoadedData` / `onCanPlay` / `onSeeked` 时立即执行 `tryCaptureVideoFrame`。
   - **首帧黑场自动检测与跳过**：采样计算画布平均亮度 `avgLuma = 0.299R + 0.587G + 0.114B`。若首帧接近纯黑（`avgLuma < 8`）且视频未在播放，自动将时间轴微移至 `0.3s` 截取清晰非黑画面。
   - **軽量级永久存储**：按最大边 `480px` 等比缩放后编码为 `data:image/jpeg;base64,...`（约 `15KB ~ 45KB`），通过 `POST /api/videos/cover` 同步写入 `videos.cover_url` 与 `community_posts.cover_url`。
2. **后端 `/api/media/prepare` 异步 `ffmpeg` 兜底**：
   - 当后端准备播放流时，后台守护线程自动检查数据库中该视频是否已有 `cover_url`；若为空，则调用 `ffmpeg -ss 0.3 -i <stream> -frames:v 1 -vf scale='min(480,iw)':-2` 自动抽帧并落库。
3. **历史无图记录“点入即生成”**：
   - 对于迁移前未存封面的历史记录，用户只需点击进入一次工作台或社区详情页，播放器加载视频流的瞬间即可自动生成并保存封面，返回列表即可看到封面图。

### 3. 左文右图精致卡片与横竖屏自适应缩略图 (`VideoCoverThumb.tsx`)

在「学习社区（`/video/community`）」、「我的学习记录（`/video/history`）」与「成员学习主页（`/video/community/users/:userId`）」中，卡片统一采用**左文右图**布局：

- **左侧信息区 (`min-w-0 flex-1`)**：顶部展示来源平台徽章与发布/测验状态，中部展示 2 行标题与 2 行 `TL;DR` 核心破局点摘要。
- **右侧缩略图 (`VideoCoverThumb`)**：
  - **双层渲染架构**：底层使用 `scale-125 object-cover opacity-55 blur-md` 渲染同源毛玻璃环境光背景，顶层使用 `object-contain` 渲染完整清晰封面。无论是抖音 `9:16` 竖屏视频还是 B 站 `16:9` 横屏视频，都能在右侧圆角矩形框内饱满呈现，绝不裁切画面主体文字。
  - **时长角标与微交互**：右下角展示半透明毛玻璃时长角标（如 `6:22`），鼠标悬停卡片时封面轻微放大并浮现播放指示图标。

### 4. 只读双栏详情页与无遮挡互动布局 (`VideoCommunityPostPage.tsx`)

- **左栏（视频播放 + 社区互动栏）**：上方为自适应横竖屏的 `VideoPlayer`，正下方紧接 `CommunityInteractBar`（`🤍 点赞`、`☆ 收藏` 与评论列表/发表框），避免互动区占用右侧空间或遮挡研报正文。
- **右栏（全高只读 `SummaryPanel`）**：完整保留「研报总结、章节导航、思维导图、字幕/文稿、测验、问答」六大 Tab，支持点击时间戳联动左侧视频跳转、一键复制 Markdown、在线双语翻译以及沙盒自测。

## 三、帖子生命周期状态机 (Post State Machine)

| 状态值 | 触发条件 | 社区广场 (`Feed`) 可见性 | 详情页表现与可执行操作 |
|---|---|---|---|
| `published` | 作者点击「🚀 发布到社区」或「更新社区展示」 | ✅ 公开展示 | 完整只读工作台 + 点赞/收藏/评论；作者可点击「下架」 |
| `outdated` | 作者在私有工作台对该视频**重新生成**了新版 AI 研报 | ✅ 公开展示（带「有新版可同步」提示） | 默认仍展示已发布的稳定快照；作者顶栏出现「更新社区展示」按钮，点击后一键指向最新 `analysis_id` 并恢复 `published` |
| `withdrawn` | 作者主动下架，或管理员在后台执行下架 | ❌ 仅在作者本人「我的发布」可见 | 外部访问返回 `404`；作者可在「我的发布」或学习记录中一键重新发布 |
| `invalid` | 源视频记录或关联分析被彻底删除（外键 `ON DELETE SET NULL`） | ❌ 列表隐藏 | 访问时提示「内容已失效」并引导返回学习社区 |

## 六、关键工程排坑实录

1. **排坑一：`SELECT p.status, a.*` 同名列覆盖导致社区详情页误报 `410 Gone` 及浏览器强缓存**
   - **现象与根因**：`community_repo.get_analysis_for_community_post` 在联表查询 `community_posts p` 与 `analyses a` 时，原先书写 `SELECT p.status, p.analysis_id, a.*`。由于 `analyses` 表同样存在 `status` 列（值为 `'done'`），字典化后 `row["status"]` 被覆盖为 `'done'`，导致路由层 `row["status"] not in ("published", "outdated")` 恒为真并返回 `HTTP 410 Gone`；更棘手的是，Chrome 遵循 RFC 9110 §15.5.11 默认将不带缓存头的 `410 Gone` 永久写入本地磁盘缓存（`from disk cache`），即使后端修复仍持续报错。
   - **解决方案**：在 SQL 中显式起别名 `SELECT p.status AS post_status`，并在路由层添加 `Cache-Control: no-store` 响应头，同时前端请求附加 `cache: 'no-store'` 与时间戳防缓存参数，编写回归单测 [`test_community.py`](file:///Users/zora/WorkData/项目app/app/DeepDiagram-Pro/SmartDiagram/apps/api-video/tests/test_community.py) 锁定契约。
2. **排坑二：React 18 自动批处理导致首帧截图中途短路未触发落库请求**
   - **现象与根因**：`VideoPlayer.tsx` 在 `tryCaptureVideoFrame` 截取首帧后，原先先调用 `setCapturedCover(dataUrl)` 与父组件回调 `onCoverCaptured(dataUrl)`（父组件随即更新 `existingCoverUrl` prop），再依赖 `useEffect` 检测 `!existingCoverUrl && capturedCover` 发起 `saveVideoCover` 请求。由于 React 18 将上述两个状态更新合并在同一渲染批次，`useEffect` 执行时 `existingCoverUrl` 已经变为非空，导致 `if (existingCoverUrl) return;` 提前短路退出。
   - **解决方案**：在 `tryCaptureVideoFrame` 生成 `dataUrl` 的同一同步调用栈直接调用 `persistCover(dataUrl)` 发送 `POST /api/videos/cover`，并在后端 `/api/media/prepare` 增加 `ffmpeg` 异步抽帧兜底，确保前后端双保险 100% 落库。
