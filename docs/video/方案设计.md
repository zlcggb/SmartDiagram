## 一、 业务背景与架构定位

### 1.1 业务痛点与第一性原理推演
全网音视频内容呈爆炸式增长，但传统的视频摄取与摘要工具普遍存在四大致命缺陷：
1. **黑盒长时等待焦虑**：传统转写方案需完整下载数十分钟视频后方可启动串行推理，用户面临长达 1 ~ 3 分钟的无反馈空白加载圈，流失率极高；
2. **专业术语同音灾难**：通用语音大模型（ASR）在处理垂直行业（金融研报、前沿架构、医学工程）音视频时，因口音方言与中英夹杂，频繁将专业词汇识别为同音错别字；
3. **内容提炼与排版割裂**：多数总结工具流于浅显的流水账，且通用 Markdown 解析器在面对 CJK 中文全角标点紧邻 `**加粗**` 时常解析失效，思维导图也无法移交至专业绘图画布继续深加工；
4. **单点存储与交互断层**：学习记录、多轮问答与测验进度若仅依赖单一本地状态，极易在跨设备或刷新时丢失。

### 1.2 系统架构核心定位
SmartDiagram 视频学习助手（`/video`）确立为**新一代 Monorepo 融合式视频学习工作台与商业智库研报系统**，其核心架构指标（SLA）为：
- **首批字幕极速上屏**：≤ 3.5 秒（首切片 180s `on_chunk_done` 极速推流，用户边看边读）；
- **6 线程并发极速转写**：`ASR_MAX_WORKERS=6`，210s 标准视频全量转写仅需 **6.7 秒**；
- **研报与双语翻译双线程并行**：`ThreadPoolExecutor` 并行调度，210s 视频端到端总耗时从 `58.8s` 压降至 **35.4 秒**（提速 40%+）；
- **双源融合极速出题**：时间桶均匀采样 + 研报骨架 + Bloom 四维分层，精选 6 题生成耗时从 `~25s` 压降至 **~9 秒**；
- **系统 1 毫秒级三层意图门控**：`Jeff :8001` (`gliformer-large-v1`) Safetensors `mmap` 零拷贝常驻（`685 MiB`），通过三层高置信门控确保开放提问 100% 精准归正；
- **主动熔断拦截时延**：≤ 200 毫秒（用户取消后强行掐断线程池并回收临时资产）。

## 三、 关键流程与任务状态机时序

### 3.1 内存状态机与四点并发极速管线驱动
后端 `apps/api-video/tasks.py` 与 `summarizer.py` 维护线程安全状态机，任务生命周期分为四个严格确定的状态阶梯：
- **`queued` (排队阶梯，进度 0% ~ 8%)**：任务完成合法性校验、URL 规范化，并在本地缓存池中进行协同匹配探测；
- **`transcribing` (声学与 6 线程并发转写阶梯，进度 8% ~ 55%)**：
  - FFmpeg 单步重采样输出 16kHz 单声道 WAV 并并发切片；
  - **6 线程切片并发 ASR (`ASR_MAX_WORKERS=6`)** 配合 `build_asr_system_prompt` 领域先验词库启动转写，首片在 **3.5s** 内触发 `on_chunk_done` 推流，210s 视频全量转写仅需 **`6.7s`**；
  - 若云端 ASR 异常，状态机平滑降级至 `local_asr` 阶梯，打点 63% ~ 92% 进度；
- **`summarizing` (双线程并行认知推理阶梯，进度 55% ~ 95%)**：通过 `ThreadPoolExecutor` 将**主研报生成**与**双语字幕翻译**双线程并行执行，消除串行等待，210s 视频端到端总耗时从 `58.8s` 压降至 **`35.4s`**；
- **`done` (双重持久化交付阶梯，进度 100%)**：全量研报、双语字幕、MindElixir 思维导图与分段耗时（`timing`）写入 **PostgreSQL 16 (`vidgrab` 库 `analyses` 表 JSONB)** 并同步前端 `localStorage`。

## 五、 边界防御、容错降级与安全机制

### 5.1 零网络等待协同下载与 HTTP 206 Range 校准机制
在生产实践中，用户常同时发起针对同一视频的“下载”与“AI 总结”。为根除重复抓取造成的外部出口带宽浪费，系统设计了 `find_existing_video_file()` 与 `wait_for_existing_download()` 缓存协调器：
```python
# apps/api-video/transcript.py 片段
existing_video = find_existing_video_file(url)
if not existing_video:
    existing_video = wait_for_existing_download(url, timeout=300.0, on_progress=_sync_progress)

if existing_video and os.path.isfile(existing_video):
    # 命中协同下载，直接在本地通过 FFmpeg 单步极速提取 16kHz WAV
    wav = _to_wav(existing_video, work_id)
```
同时，前端 `VideoPlayer.tsx` 针对未播放初始态（`readyState === 0`）点击时间戳跳转的场景内置了挂起校准队列，配合后端 HTTP 206 Range 字节流响应，实现任意时刻秒级精准跳转；`VideoDownloadCard.tsx` 下载进度达 100% 时自动触发浏览器流式保存，无需二次点击。

### 5.2 异步取消熔断器与物理资源回收
长时间音视频处理如果被用户中途抛弃，若不及时阻断将耗尽云端 API 配额与本地 CPU 算力。
- **状态流转**：调用 `/api/summary/cancel/{task_id}` 立即置位 `task["status"] = "cancelled"`；
- **主动探测**：转写、抽音与推理的每一个循环中调用 `ensure_not_cancelled(work_id)`；
- **异常拦截**：抛出 `SummaryCancelledError`，外层统一捕获并在 `finally` 块中调用 `_safe_remove()` 强制清空 `/downloads` 下的临时切片文件。
