## 二、项目背景：为什么需要这类工具？（结合公司现状）

### 2.1 公司定位（洲明科技 Unilumin）

- **业务：** LED 显示产品与解决方案提供商，覆盖国内 + 海外双线销售。
- **客户结构：** 经销商、B 端项目客户、C 端用户，签约 / 非签约客户需差异化运营。
- **产品复杂度：** 小间距、租赁、固装、创意显示等多产品线，方案讲解与配单门槛高。

### 2.2 营销数字化底盘已成型

公司已搭建 **营销全域数字化体系**，以 **Salesforce CRM** 为底座，形成：

| 主流程 | 含义 |
|--------|------|
| **MTL** | Market to Lead · 市场到线索 |
| **LTC** | Lead to Cash · 线索到回款 |
| **MCR** | Manage Customer Relationship · 客户关系管理 |
| **ITR** | Issue to Resolution · 问题到解决 |

周边已对接：OA、SAP、PBI/PLM、APS、数据中台、合同管理、企查查、400 呼叫中心、官网、社媒平台、HubSpot（海外线索）等。

### 2.3 当前缺口：培训体系是「下一块拼图」

| 已有 | 缺口 |
|------|------|
| 营销数字化系统、AI 能力规划（智能获客、销售助手、方案生成、投标、合同审查等） | **销售、渠道、工程师** 的培训、认证、实战检验 **缺乏系统化载体** |
| 数据与流程在线 | **人的能力培养** 仍依赖零散文档、线下场次 |

**思考方向（可布置给学员）：**

1. 在 MTL→LTC 全流程中，哪些环节最依赖「人学会产品知识」而非「系统自动化」？
2. AI 可以辅助培训，但「认证与实战检验」应如何设计？
3. 视频学习助手这类工具，与北森等正式培训系统是什么关系——补充、试点还是替代？

## 三、本周推荐学习：视频学习助手是什么？

### 3.1 工具定位

| 维度 | 说明 |
|------|------|
| **类型** | Docker Compose 单容器 Web 应用 |
| **场景** | 培训视频 → AI 提炼知识 → 自测巩固 |
| **核心路径** | 本地上传（优先）→ AI 总结 → 生成测验 → 作答评分 → 跳转视频片段复习 |
| **补充能力** | 链接解析、字幕、章节、思维导图、问答（链接分析为辅助入口） |

### 3.2 推荐使用流程

1. **打开首页** → 默认「本地上传」
2. **上传培训视频**（建议 5～30 分钟、有清晰讲解）
3. **等待 AI 总结完成**（大纲、要点、章节、思维导图）
4. **切换到「测验」** → 生成约 12 道题
5. **完成全部题目后提交** → 查看得分与逐题解析
6. **点击「查看视频片段」** → 回到对应时间点复习
7. **每周五复盘**：整理「学了什么 + 还有什么疑惑」发群

### 3.3 功能一览

| 功能 | 价值 | 备注 |
|------|------|------|
| AI 内容总结 | 快速掌握视频核心 | 依赖转写质量 |
| 知识框架 / 思维导图 | 结构化理解 | 适合产品、方案类培训 |
| AI 学习测验 | 检验是否真正理解 | 提交后才显示答案 |
| 视频时间点回看 | 错题回到原讲解 | 本地上传体验最佳 |
| 链接分析 | 解析外链视频 | 国内平台可能有限制 |

## 四、部署说明（导师可选用 · 技术向学员）

> 正文为**通用类型**说明；具体占位符见文末「示例对照表」。

### 4.1 适用哪类项目？

满足以下特征即可按同一套流程部署：

- 根目录有 `Dockerfile` + `compose.yaml`
- 前后端同一容器、单一端口对外（如 8000）
- 用 `.env.docker` 配置密钥与第三方 API
- 国内 ECS 需配置 Docker / PyPI 镜像加速

### 4.2 部署路径（推荐）

1. **购买阿里云 ECS**（Alibaba Cloud Linux 3）
2. **Workbench 远程连接**
3. **安装 Docker + Compose**
4. **配置镜像加速**（DaoCloud）
5. **上传代码 zip 或 git clone**
6. **修改 Dockerfile**（配置国内软件源）
7. **配置 `.env.docker`**
8. **执行部署**：`docker compose up --build -d`
9. **安全组放行应用端口**（如 8000）
10. **浏览器访问验收**

### 4.3 关键注意事项（部署侧）

| 事项 | 说明 |
|------|------|
| 国内 ECS | GitHub clone 常超时，推荐本机 `git archive` 打包上传 |
| 镜像拉取 | 必须改 Dockerfile 中 FROM 为 DaoCloud 镜像 |
| pip 安装 | Python 项目建议加清华 PyPI 源，防 Read timed out |
| 构建时间 | 首次约 15～30 分钟，建议 `nohup` 后台构建 |
| 环境变量 | 改 `.env.docker` 后需 `docker compose up -d --force-recreate` |
| 安全组 | 不放行端口则外网无法访问 |
| JWT / API Key | **勿提交 Git、勿发群、截图须打码** |

## 五、使用注意事项（全体学员必读）

### 5.1 内测阶段限制

| 限制 | 说明 |
|------|------|
| **HTTP 未加密** | 当前为 `http://IP:8000`，勿传输敏感商业 / 客户数据 |
| **数据不持久** | 服务重启或约 2 小时后，测验记录、部分任务状态会丢失 |
| **AI 外发** | 视频内容会发送给外部 LLM / ASR 服务处理，**勿上传机密素材** |
| **无正式账号体系验收** | MVP 阶段，不替代正式培训档案与认证 |
| **链接平台限制** | B 站 / YouTube 等外链解析受平台规则影响，**培训场景优先本地上传** |

### 5.2 推荐使用方式

- **适用视频：** 内部培训录屏、产品讲解、方案分享（非涉密）
- **建议时长：** 5～30 分钟为佳，过长则总结与测验耗时增加
- **学习法：** 先看 AI 总结 → 做测验 → 错题点「查看视频片段」回顾
- **人数：** 内测建议 3～10 人，便于收集反馈

### 5.3 常见问题

| 现象 | 处理 |
|------|------|
| 打不开页面 | 确认安全组已放行 8000；问管理员 |
