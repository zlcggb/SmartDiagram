# 经验：AI PPT 引擎类项目做架构评审时看什么

适用场景：本地优先的「LLM 生成演示文稿」类产品，尤其是同时存在结构化 IR 与视觉中间态（SVG/HTML）两条路径时。

## 检查清单

1. **PRD 契约 vs 导出主路径是否一致**  
   搜 `export` / `render` 入口，看真正决定交付物的是 IR、模板还是 SVG/图片。文档写「IR 优先」但代码 `if (svg) return` 是常见漂移。

2. **模型输出有没有稳定边界**  
   是否有 Zod/JSON Schema、失败重试、中文错误、Mock 适配器。没有边界的提示词链很难产品化。

3. **可编辑定义是否可验收**  
   「看起来像 PPT」≠「PowerPoint 原生文本框/形状」。需要明确哪些元素必须可编辑，哪些允许装饰降级。

4. **中间态是否被误升格为主源**  
   SVG/预览一旦变成正式导出前置条件，质检、重试、测试成本会指数上升。

5. **单体渲染器是否已失控**  
   主题模板、IR、SVG 解析挤在一个大文件时，优先拆模块再加功能。

6. **生产缺口单独记账**  
   SQLite、无鉴权、无测试、无成本上限：原型可接受，但不要和「产品完成」混谈。

## 决策启发

当「视觉效果」和「可校验交付」冲突时，若产品定位是「业务用户能改的 PPT」，应优先保住 IR/原生对象契约，把视觉链路降为预览，而不是反过来。
