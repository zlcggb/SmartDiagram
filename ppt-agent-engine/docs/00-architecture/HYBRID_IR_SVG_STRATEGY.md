# IR + SVG 相辅相成策略（2026-07-17）

## 1. 结论先说

你的理解正确：**不是 IR 或 SVG 二选一，而是分工协作。**

| 角色 | 承担什么 | 不承担什么 |
|------|----------|------------|
| **Slide IR** | 内容契约、可编辑骨架、质检、降级兜底 | 不负责「海报级」自由视觉 |
| **可编译 SVG** | 布局创意、Bento 剪影、视觉丰富度、页面预览 | 不负责未校验的业务正文权威 |
| **原生 PPTX** | 最终交付物（文本框/形状可改） | 不直接让模型写 OOXML |

一句话：

> **IR 保「能改、能控、能降级」；SVG 保「好看、有层次、有技术感」；导出时按页策略编译，而不是整条链路押一种中间态。**

## 2. 当前项目：SVG→PPT 可行性 / 执行性

### 可行性：中高（方向对，能力未完成）

已经具备：

- Gemini 提示词约束可编译子集（`rect/text/line/circle/path`、禁 foreignObject 等）
- 导出前文本 sanitize + 简易 `validateSvgPreview`（最多重试 2 次）
- `pptxgenjs` 把 SVG 元素写成原生对象（打开即可改，不依赖 Office「转形状」）
- 事实确认流水线保证内容可信度

明显缺口（对照 svg2pptx-skill）：

| 缺口 | 影响 |
|------|------|
| 正则解析，非完整 XML 树 | 复杂嵌套/`tspan`/transform 易丢 |
| 几乎无硬门禁（style/mask/渐变等） | 成功时好看，失败时静默丢元素 |
| 渐变/箭头/分组弱 | 「技术感」上限被卡住 |
| 正式导出几乎强制 SVG | IR 沦为旁路，降级路径不清晰 |
| 无回归样例 | 改 renderer 不敢大胆优化 |

### 执行性：可继续做，适合「增量增强」

| 维度 | 评估 |
|------|------|
| 产品路径 | 已通（本地闭环可导出） |
| 工程成本 | 中：先契约+门禁，再增强渲染 |
| 风险 | 中：继续只押 SVG 会放大不可控 |
| 推荐节奏 | **混合策略 + 分阶段补齐编译器**，不要推倒重来 |

**综合：可行性够用、执行性够强；优化重点是「分工清晰 + 契约硬化」，不是换技术栈。**

| 方案 | 权重 | 说明 |
|------|------|------|
| A 全面 SVG-only，弱化 IR | 52 | 视觉好，质检/降级差 |

## 4. 何时用什么（决策表）

### 4.1 按页面类型

| 页面类型 | 主路径 | 辅路径 | 原因 |
|----------|--------|--------|------|
| 封面 / 章节分隔 / 强视觉总结 | **SVG 编译优先** | IR 作内容锁定与失败降级 | 需要剪影与层次 |
| 风险表 / 行动计划表 / 数据密集页 | **IR 优先**（table/metric/timeline） | SVG 仅预览或轻装饰 | 可编辑表格/指标更重要 |
| 流程 / 架构 / 对比 Bento | **SVG 优先** | IR 保标题与关键结论文本 | 关系表达靠布局 |
| 纯文字结论 / 待确认清单 | **IR 或主题模板** | 可不生成 SVG | 成本与稳定性优先 |
| 草稿快速导出 | **IR / 主题模板** | 跳过设计模型 | 省钱省时间 |

### 4.2 按生成阶段

```text
资料 → 事实确认
      → 大纲（结构）
      → 单页策划 Plan（信息块，权威内容）
      → Slide IR（可编辑骨架：标题/要点/表格/指标）   ← 内容契约
      → 可编译 SVG（在 IR/Plan 约束下做视觉编排）   ← 视觉增强
      → 质检门禁
      → 按页策略编译 PPTX
           ├─ visual 页：SVG→原生（失败→IR）
           └─ content 页：IR→原生（SVG 仅预览）
```

关键原则：

1. **业务正文权威在 Plan/IR/事实库，不在 SVG。**  
   SVG 里的文字应来自已确认内容；sanitize 继续保留。
2. **SVG 是「布局与装饰编译源」，不是「唯一真相」。**  
   模型可以在 SVG 里重新排版，但不应发明新数字/日期。
3. **失败必须可降级。**  
   SVG 编译失败 → 同页 IR/模板导出，而不是整份 PPT 失败。

### 4.3 按导出模式（产品按钮建议）

| 模式 | 行为 | 用户感知 |
|------|------|----------|
| 快速草稿 | 只走 IR/主题模板 | 快、能改、一般好看 |
| 标准版（推荐） | 混合：视觉页 SVG，内容页 IR | 平衡 |
| 高视觉版 | 尽量全页 SVG 编译，失败降级 IR | 更好看、更贵、更慢 |

## 5. 优化路线（可执行）

### P0 — 把「相辅相成」写进契约（1–3 天量级）

1. 为每页增加 `renderStrategy`: `ir` | `svg` | `hybrid`（或由 layoutType 推断）
2. 导出优先级改为：
   - `svg/hybrid`：先 SVG 编译，失败用 IR
   - `ir`：直接 IR，SVG 只作预览
3. 从 `shared-standards` 抽一份 `COMPILABLE_SVG.md`，同步进 `prompts.ts`
4. 导出前硬门禁：禁 `style/class/mask/foreignObject`；失败触发重生成或降级

### P1 — 提高 SVG 编译上限（1–2 周）

1. 正则解析 → 轻量 XML DOM 解析
2. 支持 `tspan` 多 run、基础 `linearGradient`、箭头 `marker`
3. 拆分 `ppt-renderer`：`svg-compile` / `ir-render` / `themes`
4. 用 `references/svg2pptx-skill/examples/*.svg` 做对照回归

### P2 — 体验与成本（随后）

1. 按页重生成、按页策略切换（这一页只要稳 / 这一页要好看）
2. 设计模型只跑 `svg/hybrid` 页，降低 token
3. 可编辑等级标注（A 全文可改 / B 主体可改 / C 装饰降级）

## 6. 「更优体验」到底来自哪里？

| 体验维度 | 主要靠 |
|----------|--------|
| 内容准确、能改数字/标题 | IR + 事实确认 |
| 页面不空洞、有信息架构 | Plan + 大纲 |
| 看起来专业、有技术感 | **可编译 SVG** |
| 失败仍能交差 | IR/模板降级 |
| 成本可控 | 按页策略，不是每页都上设计模型 |

所以：SVG 不是替代 IR，而是在 IR 已经锁住「说什么」之后，解决「怎么摆、怎么显」。

## 7. 经验

这类 AI PPT 系统里，中间态最佳实践往往是：

- **语义中间态（IR/JSON）** 管正确性与可测性  
- **视觉中间态（canonical SVG）** 管布局表现力  
- **编译器** 管可编辑交付  

三者缺一，要么丑且稳，要么美但不稳。
