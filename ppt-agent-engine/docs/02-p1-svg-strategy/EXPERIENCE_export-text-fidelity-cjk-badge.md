# 经验：SVG 预览 OK ≠ PPT 换行/徽章对齐 OK

## 场景

乱码级问题修完后，用户仍报「导出字号/换行/徽章对不齐」。这是**度量漂移**，不是下载或 XML 解析失败。

## 高频坑

1. **信任 `data-h`**：编译器若用「行数 × 行高」封顶 `data-h`，会把徽章/胶囊的 padding 框压扁，`valign:middle` 看起来就不居中。
2. **CJK 字宽**：浏览器里 `data-w` 刚好装下的一行，OOXML/pptxgen 常更早折行。优先 **加宽文本框（约 +8–12%）**，不要再把字号从 0.75 往下打（易回到「小字乱码感」）。
3. **禁止用西文 0.75em 收窄中文框**：短中文标签被 `shouldTightenWidth` 收窄后必提前换行。
4. **多行应对齐策略分流**：显式 tspan / 多行 → `valign:top`；单行徽章 → `middle` + 保留框高。
5. **装饰 path**：曲线填充只能近似或跳过；主信息不进 path。

## 做法

- 回归夹具同时覆盖：橙块多行中文宽度、ROADMAP 类徽章 `data-h`、曲线 blob。
- Prompt/契约要求：徽章 `data-h`=整高；中文多行显式换行并预留 `data-w` 余量。
- 产品话术：可编辑矢量 ≈ 明显接近预览；像素级一致走可选 raster / 该页 IR。

## 可复用

凡「Web 矢量预览 → 办公文档原生对象」链路，单独测 **CJK 度量、作者给定框高、小标签 verticalAlign**，不要只测「有没有字、颜色对不对」。
