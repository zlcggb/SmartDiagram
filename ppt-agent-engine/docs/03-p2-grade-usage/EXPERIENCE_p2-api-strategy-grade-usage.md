# 经验：按页策略锁定、可编辑等级与粗用量（2026-07-17）

## 场景

Hybrid 导出落地后，常见三类缺口会反复出现：

1. 用户改了「这一页只要稳 / 要好看」，大纲一重生策略又被推断覆盖
2. 导出成功但用户不知道哪页是 SVG 真成功、哪页是 IR 降级
3. 想估成本却没有账单系统，又不能完全看不见调用次数

## 做法

1. **覆盖 + 锁定分离**：`renderStrategy` 存决策；`strategyLocked` 存「是否人工钉死」。手动 PATCH 策略默认上锁；大纲 `force` 才全量重推断。
2. **等级用纯函数贴在导出结果上**：`inferEditableGrade({ strategy, path, warning })` → A/B/C，不落库也能给前端摘要。
3. **用量只做进程内计数**：包装 AI 适配器 + `lastExportSummary`；`/api/ai/usage` 与 status 扩展字段即可，别一上来做 DB 账单。

## 踩坑

- 「DB 已有策略」不等于「用户要钉死」——未锁定时 plan/IR 应允许按新 layout **重推断**，否则首次自动值永远钉死。
- 大纲是 deleteMany + 重建：保留策略只能按 **sortOrder 下标快照**，页数变化时只能保重叠前缀。

## 复用提示

凡「运行时可推断 + 可选人工覆盖」：用 **值字段 + locked 布尔 + force 重算** 三件套；反馈类标签优先 **导出时纯函数标注**，不必事事入库。
