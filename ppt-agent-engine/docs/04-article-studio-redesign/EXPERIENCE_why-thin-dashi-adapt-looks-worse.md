# 经验：薄适配 dashi 后「颜值掉线」的根因

## 现象

融合 ThemePack / 角色 / 文案预算后，用户感觉生成页「丑、不在线」——与 dashi README 演示差距大。

## 根因排序（不是单一配色问题）

1. **缺版式资产（主因）**  
   dashi 好看靠 **1020 个人工 React 版式**；我们只借了「主题包 + 角色名」，页仍是 LLM 自由画 SVG/IR。心智对齐 ≠ 视觉对齐。

2. **可编译 SVG 约束压扁表现力**  
   禁 matrix/rotate/filter/复杂 path → 装饰与图表退化成矩形卡片 + 简陋几何，导出保真优先于设计张力。

3. **blueprint 太粗**  
   角色只有区块比例提示，没有间距/字阶/主视觉构图规范 → 易变成同质 Bento 卡片墙。

4. **配色是放大器，不是元凶**  
   12 套 token 自研近似；换色能改气质，救不了差构图。部分主题（高能橙、黑金）在烂构图上更显俗。

5. **假图表 / 装饰降级**  
   生成常塞迷你「图」；编译又近似/跳过 → 预览像未完成稿。

## 改进方向（择一深做）

| 方案 | 权重 | 说明 |
|------|------|------|
| A 自研精选版式库（每角色 3–5 个固定 SVG/IR 骨架 + 填槽） | **90** | 最接近 dashi「锁模版填文案」的颜值来源；**已落地一期变体库**见 [EXECUTION_layout-variant-library-2026-07-17.md](./EXECUTION_layout-variant-library-2026-07-17.md) |
| B 放宽预览表现力 + 导出 raster 保真 | **55** | 预览更好看，可编辑矢量变弱 |

勿误判为「再抄一套配色就能好看」。下一期可把 variant 落成真实坐标骨架文件（仍自研、不抄 dashi）。
